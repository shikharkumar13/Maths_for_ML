Mathematics for Machine Learning · Part 2

Calculus for Machine Learning

How a model actually learns: loss, slopes, gradient descent, the chain rule and backpropagation, built from zero on one running business example and taken all the way to a working neural network.

~60 min readPython 3 + NumPyNeeds Part 1 (vectors, dot products, shapes)

Think back to learning to ride a bicycle. You wobble, you lean too far left, you correct a little to the right, you wobble less. Nobody hands you the formula for balance. You learn it from a loop: try → see how wrong you were → figure out which way to adjust → adjust a little → repeat.

Every machine learning model trains with that exact loop. Part 1 gave us the machinery to make a prediction (a dot product, a matrix multiplication). This article answers the harder question: how does the model find good weights in the first place? The answer is calculus, and specifically one idea from it: the slope. If you know which way is downhill on your error, you know which way to adjust.

We will use one running story the whole way through. A marketing team has 20 months of data: how much they spent on ads and how much they sold. They want a model that predicts sales from ad spend. We'll train that model one weight at a time, then two, then switch to a classification problem, and finish with a neural network that learns a pattern no straight line can.

By the end you will be able to:

  • explain what a loss function is and why training means "minimise the loss",
  • read and compute a derivative, a partial derivative and a gradient, and say what their sign and size mean,
  • write gradient descent from scratch and diagnose a learning rate that is too small, about right or too large,
  • trace backpropagation through a computational graph and check it numerically,
  • explain vanishing gradients, why Adam is popular, and what loss.backward() in PyTorch actually does.

1Learning = minimising a loss

Intuition · archery in the dark

You're practising archery in a dark room. After each arrow, a friend calls out how far you missed the bullseye. You can't see the target, but that one number is enough to improve: try a slightly different angle, hear whether the number went up or down, adjust. The number your friend calls out is the loss. Your stance and angle are the weights.

Let's make that concrete with the marketing data. Our model is a straight line, sales = w × ad_spend + b. For now we fix the base b = 5.5 and only learn w, the extra sales each ₹1 lakh of ads brings in. To score a guess for w:

  1. predict sales for all 20 months,
  2. compute each month's error (prediction − actual),
  3. square the errors (so misses in either direction count, and big misses count a lot more),
  4. average them. That average is the mean squared error (MSE), our loss.
Math, decoded
L(w) = (1/n) Σᵢ ( w·xᵢ + b − yᵢ )²

"For each month i, take the prediction w·xᵢ + b, subtract the actual sales yᵢ, square it, then average over all n months." Notice the data (x, y) is fixed. The only thing that can change is w. So the loss is a function of the weight, and training means finding the w where it's smallest.

Try it: one slider, two views

Move w. Left: the line and its errors (vermilion). Right: the loss for that w. The curve on the right is every possible w at once.

Python
import numpy as np

rng = np.random.default_rng(7)
ad_spend = rng.uniform(1, 10, 20).round(1)                           # ₹ lakh spent on ads, 20 months
sales = (3.0 * ad_spend + 8 + rng.normal(0, 2, 20)).round(1)         # ₹ lakh of sales those months

def predict(w, b, x):
    return w * x + b                       # the model: a straight line

def mse(w, b):
    errors = predict(w, b, ad_spend) - sales
    return np.mean(errors ** 2)            # mean squared error = the loss

b = 5.5                                    # fix the base for now; we learn only w
for w in [1.0, 2.0, 3.0, 3.24, 4.0, 5.0]:
    print(f"w = {w:4}  →  loss = {mse(w, b):7.2f}")
Output
w =  1.0  →  loss =  228.19
w =  2.0  →  loss =   72.05
w =  3.0  →  loss =    5.24
w = 3.24  →  loss =    2.50
w =  4.0  →  loss =   27.77
w =  5.0  →  loss =  139.64

The loss is high when the line is too flat (w = 1), drops to about 2.5 near w ≈ 3.24, and climbs again when the line is too steep. The curve on the right of the widget is a bowl. Training is finding the bottom of the bowl.

Why squared error, and not something else?

Choosing a loss is choosing what "wrong" means. Squaring makes one big miss far worse than several small ones, and gives a smooth bowl that's easy to slide down. Other losses make other choices: absolute error (MAE) treats all misses proportionally; cross-entropy (Section 6) is the right choice for probabilities.

In business

The loss is where business priorities enter the maths. A retailer that loses far more from stock-outs than from overstock should not use a symmetric loss; an asymmetric one (such as quantile loss) pushes forecasts up. Agreeing on the loss with stakeholders is often more important than choosing the algorithm.

Check yourself

1. Errors for three months are −2, 1 and 3. What is the MSE? Answer: (4 + 1 + 9) / 3 ≈ 4.67.

2. Why is the loss written L(w) and not L(x)? Answer: during training the data is fixed; only the weights change, so the loss is a function of the weights.

2The derivative: the slope of the loss

We can see the bottom of the bowl in the widget because we drew the whole curve. A real model with a million weights can't draw its loss. It only knows the loss at the weights it currently has. So it needs a local clue: if I nudge this weight a little, does the loss go up or down, and how fast? That clue is the derivative.

Intuition · the speedometer and the nudge test

Your car's trip meter tells you how far you've gone. The speedometer tells you something different: how fast that distance is changing right now. The derivative is the speedometer of a function.

You can measure it with a nudge test: move w a tiny bit to the right and see how much the loss changes. Divide the change in loss by the size of the nudge. That ratio is the slope.

Math, decoded
L′(w) ≈ [ L(w + h) − L(w − h) ] / (2h) with h tiny, e.g. 0.0001

"Nudge a hair to the right and a hair to the left; rise over run." Textbooks write this with a limit (h → 0), which only means "make the nudge as small as you like". The two things that matter:

SlopeMeansTo reduce loss
NegativeLoss goes down as w increasesIncrease w
PositiveLoss goes up as w increasesDecrease w
ZeroFlat: at the bottom (or a flat spot)Stop
Large sizeSteep: far from the bottom, usuallyBig moves help

In one line: always move w in the opposite direction to the slope.

Try it: the tangent line

The dashed line touches the curve at w and has the same slope. Watch the sign flip as you cross the bottom.

Python
def loss_w(w):
    return mse(w, b)                        # loss as a function of the one weight we are tuning

def nudge_slope(f, w, h=1e-4):
    return (f(w + h) - f(w - h)) / (2 * h)  # nudge a tiny bit each way, see how much f moves

for w in [1.0, 3.24, 5.0]:
    print(f"w = {w:4}:  slope ≈ {nudge_slope(loss_w, w):8.2f}")
Output
w =  1.0:  slope ≈  -200.81
w = 3.24:  slope ≈    -0.70
w =  5.0:  slope ≈   156.54

Left of the bottom the slope is strongly negative (increase w). Near the bottom it's almost zero. Right of the bottom it's positive (decrease w). The nudge test works for any function, but it costs two loss evaluations per weight. With a million weights that's two million passes over the data for a single step. We need formulas.

By hand · the derivative of our loss
L(w) = (1/n) Σ ( w·xᵢ + b − yᵢ )² Call the error eᵢ = w·xᵢ + b − yᵢ. Then L = (1/n) Σ eᵢ² slope of eᵢ² with respect to eᵢ : 2·eᵢ (power rule) slope of eᵢ with respect to w : xᵢ (c·x rule; b and yᵢ are constants) multiply them (Section 5 explains why): 2·eᵢ·xᵢ L′(w) = (1/n) Σ 2·eᵢ·xᵢ = "average of 2 × error × input"

Read the result: if predictions are too high (errors positive) for months with big ad spend, the slope is positive, so lower w. That's exactly what common sense says.

Python
def dloss_dw(w, b=5.5):
    errors = predict(w, b, ad_spend) - sales
    return np.mean(2 * errors * ad_spend)   # the formula we derived by hand

for w in [1.0, 3.24, 5.0]:
    print(f"w = {w:4}:  formula = {dloss_dw(w):8.2f}   nudge = {nudge_slope(loss_w, w):8.2f}")
Output
w =  1.0:  formula =  -200.81   nudge =  -200.81
w = 3.24:  formula =    -0.70   nudge =    -0.70
w =  5.0:  formula =   156.54   nudge =   156.54

The formula and the nudge test agree to every digit shown. The formula costs one pass over the data and gives the slope for w directly. Comparing a formula against the nudge test is called a gradient check, and it is how you catch bugs in hand-written gradients (we'll do it again for a neural network in Section 7).

In ML

Every trainable model needs the slope of its loss with respect to each weight. Linear and logistic regression, neural networks and gradient boosting all use the rules in that table. Gradient boosting (XGBoost, LightGBM) even uses the second derivative, which we meet next.

In business

Economists have used derivatives for a long time under the name marginal analysis. "What extra sales does the next ₹1 lakh of ads bring?" is a derivative. So is "how much does demand drop if we raise the price by ₹1?" (price elasticity). Any time someone says "at the margin", they mean a slope.

Check yourself

1. At the current w, the slope of the loss is +40. Should you increase or decrease w? Answer: decrease. Positive slope means the loss rises as w rises.

2. What is the derivative of 5w² + 3w + 7? Answer: 10w + 3.

3Gradient descent with one weight

Intuition · walking downhill in fog

You're on a hillside in thick fog and want to reach the valley floor. You can't see the valley, but you can feel the ground under your feet. Feel which way it tilts, take a step downhill, feel again, step again. Steep ground: you're probably far from the bottom. Flat ground: you've arrived.

Math, decoded · the update rule
w_new = w_old − α × L′(w_old)

"Take the slope, scale it by the learning rate α, and step the opposite way." The minus sign does the "opposite" for you: a negative slope makes −α × slope positive, so w increases, and vice versa. Steep slopes produce big steps automatically, and the steps shrink as you approach the flat bottom.

Python
w = 0.0          # start from a bad guess
lr = 0.01        # learning rate: how big each step is

for step in range(1, 31):
    grad = dloss_dw(w)
    w = w - lr * grad                       # step AGAINST the slope
    if step in (1, 2, 3, 5, 10, 20, 30):
        print(f"step {step:2d}: w = {w:6.3f}   loss = {loss_w(w):7.3f}   slope = {dloss_dw(w):8.3f}")
Output
step  1: w =  2.901   loss =   7.855   slope =  -30.938
step  2: w =  3.211   loss =   2.559   slope =   -3.299
step  3: w =  3.244   loss =   2.499   slope =   -0.352
step  5: w =  3.248   loss =   2.498   slope =   -0.004
step 10: w =  3.248   loss =   2.498   slope =   -0.000
step 20: w =  3.248   loss =   2.498   slope =    0.000
step 30: w =  3.248   loss =   2.498   slope =    0.000

Starting from w = 0, three steps get us very close to the answer, and the slope shrinks towards zero as we arrive. That shrinking slope is also how you know when to stop: when the slope (or the improvement in loss) is below a small tolerance, or when a validation metric stops improving.

The learning rate: the one setting that makes or breaks training

Intuition · seasoning soup

The soup needs salt. A pinch at a time, tasting in between, gets you there. A grain at a time takes all evening. Tipping the shaker in at once overshoots so badly you can never recover. The learning rate is the size of the pinch.

Try it: gradient descent, step by step

Pick a learning rate and a starting point, then press Step or Run. Try 0.002, 0.01, 0.02 and 0.023.

Python
def run(lr, steps=25, w=0.0):
    for _ in range(steps):
        w = w - lr * dloss_dw(w)
    return w, loss_w(w)

for lr in [0.001, 0.01, 0.02, 0.03]:
    w_end, loss_end = run(lr)
    print(f"lr = {lr:<6} → w = {w_end:12.3f}   loss = {loss_end:14.2f}")
Output
lr = 0.001  → w =        2.935   loss =           6.87
lr = 0.01   → w =        3.248   loss =           2.50
lr = 0.02   → w =        3.256   loss =           2.50
lr = 0.03   → w =  1396471.721   loss = 87109122655643.75

Too small (0.001): after 25 steps we still haven't arrived. About right (0.01 to 0.02): we land on 3.25. Too big (0.03): every step overshoots further than the last, and the weight explodes to over a million. In real training this shows up as a loss that becomes nan or inf.

Why 0.03 explodes: curvature and the second derivative

The second derivative is the slope of the slope. It measures curvature: how quickly the ground steepens. A narrow, sharply curved bowl punishes big steps because you jump straight past the bottom and up the other side. For a bowl-shaped loss there's a neat rule: the learning rate must stay below 2 ÷ curvature.

Python
curvature = 2 * np.mean(ad_spend ** 2)     # second derivative of the loss with respect to w
print(f"curvature L''(w) = {curvature:.1f}")
print(f"largest safe learning rate ≈ 2 / curvature = {2 / curvature:.4f}")
Output
curvature L''(w) = 89.3
largest safe learning rate ≈ 2 / curvature = 0.0224

0.02 is just under the limit (it zig-zags but settles), and 0.03 is over it (it zig-zags outward forever). You can watch both in the widget above. In practice you don't compute curvature for a deep network; you try a few learning rates spaced by about 3× (0.001, 0.003, 0.01, 0.03…) and keep the largest one that trains stably.

In ML

Learning rate is the first hyperparameter to tune for any neural network. Second-derivative information is used directly by Newton's method and L-BFGS, and by XGBoost and LightGBM, which use first and second derivatives of the loss when choosing each tree's splits and leaf values.

In business

Training time is compute cost. A learning rate that's too small can multiply your cloud bill; one that's too large wastes a run that has to be restarted. Teams usually run a quick learning-rate sweep on a small sample of the data before committing to a full training job.

Check yourself

1. w = 2, slope = −30, α = 0.01. What is the new w? Answer: 2 − 0.01 × (−30) = 2.3.

2. Your training loss jumps to nan after a few steps. What's the first thing to try? Answer: lower the learning rate (and check for unscaled features).

4Two weights: partial derivatives and the gradient

Now let the model learn b too. With two weights the loss is no longer a curve; it's a surface, a landscape over the (w, b) plane. We draw it from above as a contour map, like a hiking map: each ring connects points with the same loss, and the bottom of the valley is in the middle.

Intuition · one knob at a time

A sound engineer has two knobs, bass and treble. To understand each one, she holds treble still and turns only bass, listening to the change. Then the other way round. A partial derivative is that: the slope along one weight while every other weight is frozen. The gradient collects all the partial derivatives into one vector, one entry per knob.

Math, decoded
∂L/∂w = (1/n) Σ 2·eᵢ·xᵢ (b treated as a constant) ∂L/∂b = (1/n) Σ 2·eᵢ·1 (w treated as a constant) ∇L = [ ∂L/∂w , ∂L/∂b ] the gradient: a vector (Part 1!) [w, b] ← [w, b] − α ∇L same update rule, now for a vector

Two facts make gradient descent work. The gradient points in the direction of steepest uphill, so its negative is steepest downhill. And it is always perpendicular to the contour line you're standing on: the fastest way off a level path is straight across it.

Python
def gradient(w, b, x=ad_spend):
    errors = predict(w, b, x) - sales
    dL_dw = np.mean(2 * errors * x)         # slope along w, holding b still
    dL_db = np.mean(2 * errors)             # slope along b, holding w still
    return np.array([dL_dw, dL_db])

def descend(lr, x=ad_spend, tol=1e-3, max_steps=20_000):
    params = np.array([0.0, 0.0])           # [w, b]
    for step in range(1, max_steps + 1):
        params = params - lr * gradient(*params, x=x)
        if np.linalg.norm(gradient(*params, x=x)) < tol:   # gradient ≈ 0 → at the bottom
            return params, step
    return params, max_steps

params, steps = descend(lr=0.02)
print(f"raw ad spend    : w = {params[0]:.3f}, b = {params[1]:.3f}  after {steps} steps")
print("numpy's exact fit:", np.polyfit(ad_spend, sales, 1).round(3))
Output
raw ad spend    : w = 3.241, b = 5.548  after 1285 steps
numpy's exact fit: [3.241 5.552]

We got the same answer as NumPy's exact fit, but it took 1,285 steps. Why so many for two weights? The widget shows it.

Try it: the loss landscape from above

Click anywhere to start gradient descent from that point. Then switch to scaled ad spend and try again.

With raw ad spend, the valley is a long, narrow trench. The gradient points mostly across the trench (the steep direction), so gradient descent zig-zags from wall to wall and creeps along the floor. The learning rate can't be raised to speed things up, because the steep direction would then explode (Section 3's 2 ÷ curvature limit).

Standardising the feature (mean 0, spread 1) turns the trench into a round bowl. Now the gradient points straight at the bottom.

Python
mu, sd = ad_spend.mean(), ad_spend.std()
ad_scaled = (ad_spend - mu) / sd            # standardise: mean 0, spread 1

params_s, steps_s = descend(lr=0.1, x=ad_scaled)
w_raw = params_s[0] / sd                    # convert back to "per ₹ lakh" units
b_raw = params_s[1] - params_s[0] * mu / sd
print(f"scaled ad spend : w = {w_raw:.3f}, b = {b_raw:.3f}  after {steps_s} steps")
Output
scaled ad spend : w = 3.241, b = 5.551  after 49 steps

49 steps instead of 1,285, for exactly the same model. This is the calculus reason behind the advice from Part 1 to scale your features. It's also one of the reasons deep networks use batch normalisation and layer normalisation: keeping each layer's inputs well-scaled keeps the landscape closer to round.

In ML

A neural network's gradient has one entry per weight, often millions or billions. It's still "a vector of partial derivatives", and the update is still w ← w − α∇L. Everything in later sections is either a faster way to compute ∇L (backprop) or a smarter way to use it (optimisers).

In business

Partial derivatives answer "what if we change only this?" questions: the effect of price on revenue with the ad budget held fixed, or of discount depth on margin with volume held fixed. Sensitivity tables in financial models are partial derivatives laid out in a grid.

Check yourself

1. ∇L = [4, −1]. Which way should w and b move? Answer: w down, b up (opposite signs to the gradient).

2. Gradient descent is zig-zagging and slow. Name two fixes. Answer: scale the features; use momentum or an adaptive optimiser (Section 9).

5The chain rule and computational graphs

Real models are chains: inputs go into a weighted sum, the sum goes into an activation, the activation goes into a loss. To get the slope of the loss with respect to a weight at the start of the chain, we need the chain rule.

Intuition · gears

Gear A turns gear B, which turns gear C. If B spins 3 times for every turn of A, and C spins 4 times for every turn of B, then C spins 3 × 4 = 12 times for every turn of A. Rates along a chain multiply. That is the entire chain rule.

Math, decoded
if y = f(u) and u = g(x), then dy/dx = dy/du × du/dx

"Slope of the outside (at the inside value) times slope of the inside." It can be as long as you need: dL/dw = dL/dp × dp/dz × dz/dw.

By hand
y = (3x + 2)⁴ inside u = 3x + 2 du/dx = 3 outside y = u⁴ dy/du = 4u³ dy/dx = 4(3x + 2)³ × 3 at x = 0: 4 × 8 × 3 = 96
Python
# y = (3x + 2)^4.  Inside: u = 3x + 2 (du/dx = 3).  Outside: y = u^4 (dy/du = 4u^3)
def y(x):           return (3 * x + 2) ** 4
def dy_dx_chain(x): return 4 * (3 * x + 2) ** 3 * 3    # outer slope × inner slope

for x in [-1.0, 0.0, 1.0]:
    print(f"x = {x:4}:  chain rule = {dy_dx_chain(x):8.1f}   nudge = {nudge_slope(y, x):8.1f}")
Output
x = -1.0:  chain rule =    -12.0   nudge =    -12.0
x =  0.0:  chain rule =     96.0   nudge =     96.0
x =  1.0:  chain rule =   1500.0   nudge =   1500.0

Computational graphs: the chain rule as a picture

Draw every small operation as a box and connect them in order. That drawing is a computational graph. Here is one neuron classifying one example (input x = 2, true label 1), using the sigmoid and the "log loss" you'll meet properly in Section 6.

Training on this graph happens in two sweeps:

  • Forward pass (left to right): compute each box's value and remember it.
  • Backward pass (right to left): start with "the slope of L with respect to itself is 1". At each box, multiply the incoming slope by that box's local slope and pass it left. When you reach a weight, you have its gradient.

Try it: forward, then backward

Step through. Values (petrol) flow right; gradients (vermilion) flow left. Change w or b and step again.

true label y = 1
Python
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

x, y_true = 2.0, 1.0          # one training example (label 1)
w, b = 0.5, -0.5              # current weights

# ---- forward: compute and remember every intermediate value ----
z = w * x + b                 # 0.5
p = sigmoid(z)                # predicted probability
L = -np.log(p)                # loss when the true label is 1

# ---- backward: local slopes, multiplied right to left ----
dL_dp = -1 / p                # slope of -log(p)
dp_dz = p * (1 - p)           # slope of the sigmoid
dL_dz = dL_dp * dp_dz         # chain rule
dL_dw = dL_dz * x             # z = w·x + b  → dz/dw = x
dL_db = dL_dz * 1             #              → dz/db = 1

print(f"forward : z = {z:.4f}, p = {p:.4f}, L = {L:.4f}")
print(f"backward: dL/dz = {dL_dz:.4f}  (equals p − y = {p - y_true:.4f})")
print(f"          dL/dw = {dL_dw:.4f},  dL/db = {dL_db:.4f}")
Output
forward : z = 0.5000, p = 0.6225, L = 0.4741
backward: dL/dz = -0.3775  (equals p − y = -0.3775)
          dL/dw = -0.7551,  dL/db = -0.3775

Look at the second output line. The two messy local slopes, −1/p from the log and p(1 − p) from the sigmoid, multiply out to simply p − y: predicted probability minus true label. That tidy result is no accident, and it's the main reason sigmoid and log loss are always used together.

In ML

The computational graph is how every deep-learning framework sees your model. PyTorch, TensorFlow and JAX record the forward pass as a graph, then run the backward sweep automatically. Section 11 builds a tiny version of that engine. Backpropagation is nothing more than the chain rule applied to this graph, reusing the values saved on the way forward.

In business

Business metrics are chains too: price → demand → revenue → profit. If raising price by ₹1 cuts demand by 50 units, and each unit is worth ₹200 of profit, the effect of price on profit through that path is −50 × 200 = −₹10,000. That is the chain rule. It's what driver-tree models in FP&A teams compute.

Check yourself

1. y = (5x)² . What is dy/dx? Answer: 2(5x) × 5 = 50x.

2. Why must the forward pass store its intermediate values? Answer: the backward pass needs them to compute each local slope (for example p(1 − p) needs p).

6Logistic regression and cross-entropy

Our marketing model predicted a number. Many business questions need a probability instead: will this borrower default? will this customer churn? Logistic regression takes the familiar weighted sum z = w·x + b and squashes it through the sigmoid, p = σ(z), into a value between 0 and 1.

Why not just use squared error?

Intuition · a confident wrong answer deserves a loud correction

A student who answers "definitely B" when the answer is A needs a strong correction, more than one who said "maybe A or B". A good loss should give a big slope when the model is confidently wrong. Squared error on top of a sigmoid does the opposite: when the sigmoid is saturated (p near 0 or 1), its slope is almost zero, and that tiny number gets multiplied into the gradient.

Math, decoded · binary cross-entropy (log loss)
L = −[ y·log(p) + (1 − y)·log(1 − p) ] averaged over examples

Only one of the two terms is "on" for each example. If y = 1, the loss is −log(p): near 0 when p ≈ 1, huge when p ≈ 0. If y = 0, it's −log(1 − p). Combined with the sigmoid, its slope with respect to z is just p − y (Section 5).

Python
y_true = 1.0
for z in [-6.0, -2.0, 0.0, 2.0]:
    p = sigmoid(z)
    grad_mse = 2 * (p - y_true) * p * (1 - p)     # d/dz of (p − y)²
    grad_ce  = p - y_true                          # d/dz of cross-entropy
    print(f"z = {z:5}  p = {p:.4f}   MSE grad = {grad_mse:8.4f}   cross-entropy grad = {grad_ce:8.4f}")

Training a loan-default model from scratch

A lender has 400 past loans with two standardised features, credit score and debt-to-income ratio, and whether each loan defaulted. The whole training loop is the gradient descent you already know, using p − y as the error signal and Part 1's matrix multiplication to handle all 400 loans at once.

Python
rng = np.random.default_rng(1)
n = 400
credit = rng.normal(0, 1, n)                  # standardised credit score
dti    = rng.normal(0, 1, n)                  # standardised debt-to-income ratio
true_logit = -1.0 - 1.8 * credit + 1.4 * dti
default = (rng.uniform(size=n) < sigmoid(true_logit)).astype(float)   # 1 = defaulted

X = np.column_stack([credit, dti])
w, b, lr = np.zeros(2), 0.0, 0.5

for epoch in range(1, 301):
    p = sigmoid(X @ w + b)                     # forward: probabilities for all 400
    grad_z = (p - default) / n                 # the famous p − y (averaged)
    w -= lr * (X.T @ grad_z)                   # chain rule: dz/dw = x
    b -= lr * grad_z.sum()
    if epoch in (1, 10, 50, 300):
        loss = -np.mean(default * np.log(p) + (1 - default) * np.log(1 - p))
        acc = np.mean((p > 0.5) == default)
        print(f"epoch {epoch:3d}: loss = {loss:.4f}  accuracy = {acc:.1%}  w = {w.round(2)}  b = {b:.2f}")

In ML

Softmax + cross-entropy is the multi-class version, and it's the output layer of almost every classifier: image models, text classifiers, and language models predicting the next token. Its gradient with respect to the scores is again "predicted probabilities minus the one-hot truth". If you understand p − y, you understand the last layer of GPT-style training.

In business

Credit-risk scorecards, churn propensity, fraud scoring and click-through prediction are logistic regression or its descendants. Because the output is a probability, it plugs straight into expected-value decisions: approve the loan if p × loss_if_default is less than the expected interest earned.

7Backpropagation in a real neural network

Linear and logistic models draw straight lines. Plenty of business patterns aren't straight: customers respond to an offer only in a middle band of age and income, not at either extreme. Here's such a pattern: class 1 sits inside a circle.

Python
rng = np.random.default_rng(0)
n = 400
Xc = rng.uniform(-1, 1, size=(n, 2))                     # two features, e.g. scaled age & income
yc = (np.sum(Xc ** 2, axis=1) < 0.45).astype(float)      # class 1 = inside a circle

# A straight-line model can't draw a circle:
w, b = np.zeros(2), 0.0
for _ in range(2000):
    p = sigmoid(Xc @ w + b)
    w -= 0.5 * Xc.T @ (p - yc) / n
    b -= 0.5 * np.mean(p - yc)
print(f"logistic regression accuracy: {np.mean((p > 0.5) == yc):.1%}  (class-1 share: {yc.mean():.1%})")
Output
logistic regression accuracy: 63.2%  (class-1 share: 36.8%)

63.2% accuracy is the same as always guessing "class 0" (63.2% of points are class 0). A straight line simply can't wrap around a circle. We need a hidden layer.

The network and its backward pass

Intuition · blame flows backwards

A factory's product fails inspection. The inspector asks the last station how much its output contributed, then asks the station before that, and so on, multiplying sensitivities as she walks back up the line. Backpropagation is that walk. At each layer it does two things: work out the gradient for that layer's weights, and pass the blame further back through those same weights (a transpose, from Part 1).

Math, decoded · the four lines of backprop
dZ2 = p − y output error (Section 5's gift) dW2 = Hᵀ @ dZ2 gradient for layer-2 weights dH = dZ2 @ W2ᵀ send the error back through W2 dZ1 = dH ⊙ (1 − H²) through tanh: multiply by its local slope dW1 = Xᵀ @ dZ1 gradient for layer-1 weights

Every line is Part 1 (matrix multiplication, transpose, element-wise product) combined with Section 5 (multiply by the local slope). Deeper networks just repeat the middle pair once per extra layer.

Python
def init(hidden=8, seed=0):
    r = np.random.default_rng(seed)
    return {"W1": r.normal(0, 1, (2, hidden)), "b1": np.zeros(hidden),
            "W2": r.normal(0, 1, (hidden, 1)) / np.sqrt(hidden), "b2": np.zeros(1)}

def forward(P, X):
    Z1 = X @ P["W1"] + P["b1"]          # (n, 8)
    H  = np.tanh(Z1)                    # hidden layer
    Z2 = H @ P["W2"] + P["b2"]          # (n, 1)
    p  = sigmoid(Z2).ravel()            # (n,)
    return Z1, H, p

def loss_fn(P, X, y):
    _, _, p = forward(P, X)
    p = np.clip(p, 1e-9, 1 - 1e-9)
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

def backward(P, X, y):
    Z1, H, p = forward(P, X)
    dZ2 = ((p - y) / len(y))[:, None]   # output layer: p − y again   (n, 1)
    dW2 = H.T @ dZ2                     # (8, 1)
    db2 = dZ2.sum(axis=0)
    dH  = dZ2 @ P["W2"].T               # send the error back through W2   (n, 8)
    dZ1 = dH * (1 - H ** 2)             # through tanh: slope is 1 − tanh²
    dW1 = X.T @ dZ1                     # (2, 8)
    db1 = dZ1.sum(axis=0)
    return {"W1": dW1, "b1": db1, "W2": dW2, "b2": db2}

Hand-written backprop is easy to get subtly wrong, so we check it against the nudge test from Section 2 on a few individual weights:

    P[name][idx] = old - h; down = loss_fn(P, Xc, yc)
    P[name][idx] = old

In ML

CNNs, RNNs and transformers are trained with exactly this procedure; only the layers differ. Convolution layers and attention layers each have their own local slope rules, and backprop chains them together. In RNNs it's called backpropagation through time, because the chain runs back across time steps.

In business

Non-linear patterns are common: response that peaks at mid-range prices, risk that rises only when two factors are both high. Tree ensembles and neural networks both capture them. Knowing that a linear model is stuck at the "always say no" baseline, as above, is the signal to reach for one.

Check yourself

1. Why does backprop compute dH = dZ2 @ W2ᵀ with a transpose? Answer: W2 maps 8 hidden units to 1 output; going backwards you map 1 error to 8 hidden units, which needs the transposed shape (Part 1, Section 5).

2. What is a gradient check, and when should you run one? Answer: comparing backprop's gradient to a nudge-test estimate; run it whenever you hand-write gradients or a custom layer.

8Vanishing and exploding gradients

Backprop multiplies a local slope at every layer. Multiply many numbers together and two things can happen: if they're mostly below 1, the product shrinks towards zero; if they're mostly above 1, it blows up. Deep networks live or die by this.

Intuition · a photocopy of a photocopy

Photocopy a page, then copy the copy, and repeat twenty times. If each copy is a bit fainter, the twentieth is blank. If each copy is a bit darker, it's a black smudge. Each layer in backprop is one more photocopy of the error signal. The sigmoid's slope is at most 0.25, so with sigmoid layers every copy is fainter.

Try it: the multiplication chain

A simplified model: each layer multiplies the gradient by the same factor. Real networks vary layer to layer, but the effect is the same.

Here is a real experiment rather than a toy: build networks of increasing depth, run one backward pass, and measure how large the gradient is when it reaches the first layer.

Python
def first_layer_grad(depth, act, width=32, seed=0):
    r = np.random.default_rng(seed)
    X = r.normal(0, 1, (64, width))
    Ws, Hs, Zs = [], [X], []
    for _ in range(depth):                                   # forward through `depth` layers
        scale = np.sqrt(2 / width) if act == "relu" else np.sqrt(1 / width)
        W = r.normal(0, scale, (width, width)); Ws.append(W)
        Z = Hs[-1] @ W; Zs.append(Z)
        Hs.append(np.maximum(0, Z) if act == "relu" else sigmoid(Z))
    dH = np.ones_like(Hs[-1]) / 64                           # pretend loss = mean of outputs
    for i in reversed(range(depth)):                         # backward, layer by layer
        local = (Zs[i] > 0).astype(float) if act == "relu" else Hs[i+1] * (1 - Hs[i+1])
        dZ = dH * local
        if i == 0:
            return np.linalg.norm(Hs[0].T @ dZ)              # size of gradient reaching layer 1
        dH = dZ @ Ws[i].T

for depth in [2, 5, 10, 20, 30]:
    print(f"depth {depth:2d}:  sigmoid → {first_layer_grad(depth, 'sigmoid'):.2e}   "
          f"relu → {first_layer_grad(depth, 'relu'):.2e}")

depth  5:  sigmoid → 3.53e-03   relu → 8.23e+00

With sigmoid, the first layer of a 30-layer network gets a gradient around 10⁻¹⁹. It effectively stops learning while later layers carry on. With ReLU and matched initialisation, the gradient stays roughly the same size at every depth.

The standard fixes, and what each one does

FixHow it helps
ReLU-family activationsSlope is exactly 1 for positive inputs, so the signal isn't shrunk. (Caveat: a neuron whose input is always negative has slope 0 and stops learning, a "dead ReLU". Leaky ReLU and GELU soften this.)
Careful initialisationXavier/Glorot (for tanh/sigmoid) and He (for ReLU) choose the starting weight scale so the signal neither grows nor shrinks layer to layer. The experiment above used both.
Residual (skip) connectionsResNets and transformers add a layer's input back to its output, out = x + layer(x). The "+ x" gives the gradient a direct path backwards with slope 1.
Normalisation layersBatch norm and layer norm keep activations in a sensible range, which keeps local slopes away from the flat ends.
Gating (LSTM, GRU)Recurrent networks use gates to control how much signal passes through time, reducing vanishing gradients over long sequences.
Gradient clippingFor exploding gradients: if the gradient is too long, shrink it to a maximum length while keeping its direction.
Python
def clip_by_norm(grad, max_norm=5.0):
    norm = np.linalg.norm(grad)
    if norm > max_norm:
        grad = grad * (max_norm / norm)     # same direction, capped length
    return grad

g = np.array([300.0, -400.0])               # an "exploded" gradient, length 500

2. Why does out = x + layer(x) help gradients? Answer: the derivative of the "+ x" path is 1, so some gradient always passes straight through.

9Mini-batches, momentum, RMSProp and Adam

Mini-batches: estimate the slope from a sample

Intuition · tasting a spoonful

To check whether a big pot of soup needs salt, you taste a spoonful, not the whole pot. The spoonful gives a slightly noisy but fast answer. Computing the gradient on all of the data for every step (batch gradient descent) is tasting the whole pot. Using one example (stochastic gradient descent) is tasting one drop. A mini-batch of 32 to 512 examples is the spoonful, and it's what almost everyone uses.

The mini-batch gradient points roughly downhill, with some noise. Much faster steps more than make up for the noise, and the noise even helps a little, nudging the model out of flat spots and shallow dips. One full pass over the data is called an epoch.

Smarter steps

Plain gradient descent struggled in the stretched valley of Section 4. Three classic upgrades target that problem:

OptimiserAnalogyIdea
MomentumA ball rolling downhill builds speedKeep a running average of past gradients. Consistent directions add up; zig-zags across the valley cancel out.
RMSPropA hiker who shortens her stride on steep, jumpy groundKeep a running average of each gradient's size, and divide by it. Steep directions get smaller steps, shallow directions bigger ones. Each weight gets its own effective learning rate.
AdamBoth of the aboveMomentum for direction plus RMSProp for step size, with a small correction for the first few steps.
Python
# A stretched valley: steep across (w2), shallow along (w1) — like unscaled features
def valley_loss(p): return 0.5 * (p[0] ** 2 + 25 * p[1] ** 2)
def valley_grad(p): return np.array([p[0], 25 * p[1]])

def sgd(p, g, s, lr):      return p - lr * g, s
def momentum(p, g, s, lr, beta=0.9):
    s["v"] = beta * s.get("v", 0) + g                      # running direction
    return p - lr * s["v"], s
def rmsprop(p, g, s, lr, beta=0.9, eps=1e-8):
    s["sq"] = beta * s.get("sq", 0) + (1 - beta) * g ** 2  # running size of each slope
    return p - lr * g / (np.sqrt(s["sq"]) + eps), s
def adam(p, g, s, lr, b1=0.9, b2=0.999, eps=1e-8):
    s["t"] = s.get("t", 0) + 1
    s["m"] = b1 * s.get("m", 0) + (1 - b1) * g             # momentum part
    s["v"] = b2 * s.get("v", 0) + (1 - b2) * g ** 2        # RMSProp part
    m_hat = s["m"] / (1 - b1 ** s["t"])                    # early-step bias correction
    v_hat = s["v"] / (1 - b2 ** s["t"])
    return p - lr * m_hat / (np.sqrt(v_hat) + eps), s

def steps_to_converge(opt, lr, start=(-4.0, 1.5), tol=1e-4, max_steps=5000):
    p, s = np.array(start), {}
    for t in range(1, max_steps + 1):
        p, s = opt(p, valley_grad(p), s, lr)
        if not np.all(np.isfinite(p)) or valley_loss(p) > 1e6:
            return None                                    # diverged
        if valley_loss(p) < tol:
            return t
    return None

# Fair comparison: give every optimiser its own best learning rate from the same grid
grid = [0.001, 0.003, 0.01, 0.03, 0.05, 0.07, 0.1, 0.3, 0.5, 1.0]
for name, opt in [("SGD", sgd), ("Momentum", momentum), ("RMSProp", rmsprop), ("Adam", adam)]:
    results = {lr: steps_to_converge(opt, lr) for lr in grid}
    ok = {lr: s for lr, s in results.items() if s}
    best_lr = min(ok, key=ok.get)
    print(f"{name:9s} best lr = {best_lr:<5}  steps = {ok[best_lr]:4d}   (diverged at {sum(v is None for v in results.values())} of {len(grid)} rates)")
Output

Read these results honestly:

  • On this particular valley, RMSProp reached the bottom fastest. Plain SGD and momentum tied, and Adam was slowest in steps.
  • But look at the right-hand column. SGD diverged at half of the learning rates in the grid; Adam diverged at only one. Adam's real strength is robustness: it trains reasonably across a wide range of settings and on very different layers at once. That is why it (and its variant AdamW) became the default for deep learning, not because it always wins a race.
  • Results depend on the problem. Well-tuned SGD with momentum is still a strong choice for some vision models.

10Learning-rate schedules

Intuition · parking a car

Pulling out of a parking space, you start slowly. On the open road you drive at full speed. Approaching your spot, you slow right down to place the car precisely. A learning-rate schedule does the same: a short warmup while the random starting weights produce wild gradients, full speed in the middle, then a gradual decay so the final steps can settle into the bottom of the valley instead of bouncing around it.

def warmup_cosine(step, total=1000, warmup=100, lr_max=1e-3, lr_min=1e-5):
    if step < warmup:
        return lr_max * (step + 1) / warmup                  # ramp up gently
    progress = (step - warmup) / (total - warmup)            # 0 → 1 after warmup
    return lr_min + 0.5 * (lr_max - lr_min) * (1 + np.cos(np.pi * progress))

11How autograd works (what PyTorch does)

In Section 7 we wrote backprop by hand for one specific network. Frameworks do it automatically for any network you can write. The trick: make every number remember which operation produced it and how to pass a gradient back through that operation. Then backward() just walks the computational graph in reverse. Here's a complete working version in about 50 lines.

Python
import math

class Value:
    """A number that remembers how it was made, so it can send gradients back."""
    def __init__(self, data, parents=(), op=""):
        self.data, self.grad = data, 0.0
        self._parents, self._op = parents, op
        self._backward = lambda: None

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():                       # d(a+b)/da = 1, d(a+b)/db = 1
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():                       # d(ab)/da = b, d(ab)/db = a
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def sigmoid(self):
        s = 1 / (1 + math.exp(-self.data))
        out = Value(s, (self,), "sigmoid")
        def _backward():
            self.grad += s * (1 - s) * out.grad
        out._backward = _backward
        return out

    def log(self):
        out = Value(math.log(self.data), (self,), "log")
        def _backward():
            self.grad += (1 / self.data) * out.grad
        out._backward = _backward
        return out

    def backward(self):
        order, seen = [], set()
        def visit(v):                          # topological order: parents before children
            if v not in seen:
                seen.add(v)
                for p in v._parents:
                    visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0                        # dL/dL = 1
        for v in reversed(order):              # walk the graph backwards
            v._backward()

Each operation stores a tiny _backward function containing its local slope rule from the table in Section 2. Now rebuild the one-neuron example from Section 5 and let the engine do the calculus:

Python
w, b, x = Value(0.5), Value(-0.5), Value(2.0)
L = ((w * x + b).sigmoid().log()) * -1      # same one-neuron example as Section 5
L.backward()
print(f"L = {L.data:.4f}   dL/dw = {w.grad:.4f}   dL/db = {b.grad:.4f}")

Common mistakes and fixes

Mistakes and fixes
  1. Stepping with the gradient. w += lr * grad climbs uphill. The update subtracts.
  2. Loss becomes nan. Learning rate too high, unscaled features, or log(0). Lower the rate, scale inputs, clip probabilities before taking logs.
  3. Training is painfully slow. Features on very different scales (zig-zag valley). Standardise them.
  4. MSE for classification. Use cross-entropy; MSE + sigmoid gives weak gradients when confidently wrong.
  5. Trusting hand-written gradients. Run a gradient check against the nudge test.
  6. Deep sigmoid networks. Use ReLU-family activations with He initialisation, and residual connections for depth.
  7. Reading training accuracy as success. Always check on held-out data.

Wrapping up the series

Part 1 gave you the language: data as vectors and matrices, predictions as dot products, layers as matrix multiplications. Part 2 gave you the engine: a loss to measure error, derivatives to find which way is downhill, the chain rule to push that information back through every layer, and update rules to take the step. The bicycle loop from the introduction (try, measure, adjust, repeat) is now something you can write in NumPy. Every algorithm in the rest of the series, from regularised regression to gradient boosting to transformers, is a variation on these two parts.
