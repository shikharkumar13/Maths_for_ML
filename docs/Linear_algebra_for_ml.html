Mathematics for Machine Learning · Part 1

Linear Algebra for Machine Learning

Vectors, matrices, dot products and matrix multiplication from zero, with pictures you can drag, code that runs, and the business problems each idea solves.

~50 min readPython 3 + NumPyNo prior maths assumed

Describe a friend to someone who has never met them. You might say: 31 years old, works in finance, loves action films, drinks four coffees a day. Without noticing, you just wrote down a list of numbers and categories in a fixed order. That list is a vector. Write the same list for every customer of a bank and stack them up, and you have a matrix.

Machine learning needs to do two things with such lists: compare them (is this transaction like the fraudulent ones?) and transform them (turn raw features into a credit score). Linear algebra is the toolkit for both. It is less about clever proofs and more about bookkeeping: storing numbers in the right shape and combining them efficiently.

By the end of this article you will be able to:

  • read the notation in ML papers and documentation without freezing,
  • predict the shape of any NumPy result before you run it, which is where most real bugs come from,
  • explain what a dot product, a matrix multiplication and a determinant mean, not just how to compute them,
  • see these operations inside linear regression, recommenders, neural networks and attention.

The three golden rules for this article

1. Rows are examples, columns are features. A dataset X has shape (n_samples, n_features). NumPy, pandas, scikit-learn and PyTorch all use this convention, and so does every example here. You will always see X @ W, never the other way round.

2. @ and * are different. In NumPy, @ is the dot product / matrix multiplication. * multiplies entry by entry. Mixing them up is the most common silent bug in ML code.

3. Say the shapes out loud. Before you run a line, predict the output shape. "(500, 20) times (20, 8) gives (500, 8)." If you can't predict it, that line is where the bug will be.

1Scalars, vectors, matrices and shapes

Intuition · a hospital visit

The nurse writes your temperature: 37.2. One number. That is a scalar.

The lab sends your blood panel: haemoglobin, white cells, platelets, glucose, creatinine. Five numbers in a fixed order. That is a vector. The order matters: swap glucose and platelets and the report becomes nonsense.

The hospital keeps every patient's panel for the month in one table, one patient per row and one test per column. That is a matrix.

Every machine learning dataset is a matrix of that kind. One row describes one example (a customer, a house, a transaction). One column holds one feature (age, area, amount) for every example.

What does "dimension" mean?

The word scares people because it sounds like science fiction. In ML it means something plain: the number of entries in a vector. A customer described by age, income, credit score and products held is a point in 4-dimensional space. A 28×28 grayscale image flattened into one long list is a point in 784-dimensional space, one dimension per pixel.

Nobody can picture 784 dimensions, and you don't need to. Here is the useful trick: everything in this article works the same way in 2 dimensions as in 2,000. We draw pictures in 2D to build intuition, then trust the algebra to carry it up.

When data has more than two axes (a batch of colour images is images × height × width × channels), people call it a tensor. A tensor is just the next step up the same ladder: scalar (0 axes), vector (1 axis), matrix (2 axes), tensor (3 or more).

Try it: rows, columns and shapes

Click a customer's name to pull out a row. Click a column header to pull out a feature. Watch the shape.

Python
import numpy as np

# 5 customers (rows) x 4 features (columns): age, income (₹), credit score, products held
X = np.array([
    [34,  75_000, 720, 3],
    [28,  52_000, 680, 1],
    [45,  92_000, 780, 5],
    [23,  38_000, 620, 0],
    [52, 115_000, 810, 7],
])

print("Shape of X          :", X.shape)      # (rows, columns)
print("Customer 3 (a row)  :", X[2])         # Python counts from 0
print("Income (a column)   :", X[:, 1])
print("Their shapes        :", X[2].shape, X[:, 1].shape)
Output
Shape of X          : (5, 4)
Customer 3 (a row)  : [   45 92000   780     5]
Income (a column)   : [ 75000  52000  92000  38000 115000]
Their shapes        : (4,) (5,)

Notice the two shapes at the bottom. A row has 4 numbers, one per feature, so its shape is (4,). A column has 5 numbers, one per customer, so its shape is (5,). The trailing comma is Python's way of writing a one-item tuple: "a 1-D array of length 4".

Common mistake · (n,) is not (n, 1)

A 1-D array of 3 numbers has shape (3,). A column of 3 numbers has shape (3, 1). They hold the same numbers but behave differently. Add a (3,) to a (3, 1) and NumPy quietly builds a (3, 3) grid instead of raising an error. If a result suddenly has more entries than you expected, check this first.

Python
v = np.array([1, 2, 3])
col = v.reshape(-1, 1)          # same numbers, stacked as a column
print(v.shape, "vs", col.shape)
Output
(3,) vs (3, 1)
In ML

The X you pass to model.fit(X, y) in scikit-learn is exactly this kind of matrix: shape (n_samples, n_features). The target y is a vector with one entry per row of X.

In business

Every table in your data warehouse, every CSV export, every "customer 360" view is a matrix. Once you see it that way, the question "can we model this?" turns into "can we get it into rows of examples and columns of features?"

Check yourself (3 questions)

1. You have 10,000 images, each 28×28 pixels, flattened. What is the shape of the dataset matrix? Answer: (10000, 784). Rows are images; 28 × 28 = 784 pixel columns.

2. In the customer matrix above, what is X[4, 2]? Answer: 810, the credit score (column 2) of the fifth customer (row 4).

3. Is "city" (Mumbai, Pune, Delhi) a number you can put straight into a vector? Answer: Not directly. It has to be encoded first, for example one-hot encoding turns it into three 0/1 columns.

2Vectors as arrows: adding and scaling

A vector has two faces, and switching between them is half of linear algebra.

  • A list of numbers. [2, 1, 0, 3] could be a shopping basket: 2 milk, 1 bread, 0 eggs, 3 bananas.
  • An arrow. [2, 1] is an arrow that goes 2 steps right and 1 step up. It has a direction and a length. Where you draw it doesn't matter: slide it anywhere and it is still the same vector.

The list view is how computers store vectors. The arrow view is how humans understand them. We will use both.

Adding vectors

Intuition · two legs of a walk

Walk 2 blocks east and 1 north. Then walk 1 east and 3 north. Where are you? 3 east and 4 north. Adding vectors means doing one journey and then the other. On paper: put the tail of the second arrow at the tip of the first. The arrow from the start to the final tip is the sum.

By hand
a = [2, 1] b = [1, 3] a + b = [2+1, 1+3] = [3, 4] ← add matching positions a − b = [2−1, 1−3] = [1, −2] 2a = [2×2, 2×1] = [4, 2] ← multiply every entry

The only rule: both vectors must be the same length. You can't add a 3-item basket to a 4-item basket; the positions wouldn't mean the same thing.

Subtracting vectors: the "gap" between two things

a − b is the arrow that goes from the tip of b to the tip of a. It answers "how do I get from b to a?" In ML this gap has a name: the error. If a is what the model predicted and b is what actually happened, a − b tells you how far off you were, and in which direction, for every example at once.

Scaling a vector

Intuition · a volume knob

Multiplying a vector by a number (a scalar) is like turning a volume knob. The song stays the same, it just gets louder or quieter. Multiply by 2 and the arrow doubles in length. Multiply by 0.5 and it halves. Multiply by −1 and it flips to point the opposite way.

Try it: the vector playground

Drag the a and b handles. Move the slider to scale a. Switch between a + b and a − b.

Things to notice while you play: with a − b, the dashed arrow from b's tip to a's tip is exactly the same arrow as a − b drawn from the origin. Set the slider to −1 and a flips. Set it to 0 and a shrinks to nothing.

Python
monday  = np.array([2, 1, 0, 3])   # milk, bread, eggs, bananas
tuesday = np.array([1, 0, 2, 1])

print("Both days   :", monday + tuesday)
print("Difference  :", monday - tuesday)
print("Double order:", 2 * monday)
Output
Both days   : [3 1 2 4]
Difference  : [ 1  1 -2  2]
Double order: [4 2 0 6]
Python
actual    = np.array([310, 205, 480])   # true sales for 3 stores
predicted = np.array([300, 220, 470])   # what the model forecast
print("Error vector:", predicted - actual)

segment = np.array([[0.20, 0.80, 0.60],
                    [0.30, 0.70, 0.50],
                    [0.25, 0.75, 0.55]])
print("Centroid    :", segment.mean(axis=0))   # add the vectors, divide by 3
Output
Error vector: [-10  15 -10]
Centroid    : [0.25 0.75 0.55]
In ML
  • Error vectors. predicted − actual is the starting point of every loss function you will meet in Article 2.
  • Centroids. K-means clustering finds the "average customer" of each segment by adding the vectors in the group and dividing by the count, exactly like the code above.
  • Learning. Gradient descent updates a model with w_new = w − α · g: subtract a scaled-down vector from the weights. That one line is vector subtraction plus scalar multiplication. Article 2 explains where g comes from.
  • Word arithmetic. In word-embedding models such as word2vec, researchers found that king − man + woman lands close to queen. Subtraction captured a "direction" of meaning.
In business

A retailer stores each store's daily sales as a vector over products. Adding the vectors gives weekly totals. Subtracting forecast from actual gives a per-product error vector, which tells the planning team which items the forecast got wrong, not just by how much overall.

Check yourself

1. What is [3, −1] + [−3, 1]? Answer: [0, 0]. They are opposite arrows and cancel out.

2. A model predicted [50, 80], the truth was [45, 90]. What is the error vector, and which prediction was too low? Answer: [5, −10]. The second prediction was 10 too low.

3Length and distance (norms)

Once data points are arrows, two natural questions follow: how long is this arrow, and how far apart are these two points? A norm is a way of measuring length. There are two you must know.

Intuition · the crow and the taxi

You are at a corner and the café is 3 blocks east and 4 blocks north. A crow flies straight there: 5 blocks (Pythagoras). A taxi has to follow the streets: 3 + 4 = 7 blocks. Same start, same end, two honest answers. The crow's distance is the L2 norm. The taxi's distance is the L1 norm (also called Manhattan distance).

Math, decoded
‖v‖₂ = √(v₁² + v₂² + … + vₙ²) "square each entry, add, take the root" ‖v‖₁ = |v₁| + |v₂| + … + |vₙ| "drop the signs and add" distance(a, b) = ‖a − b‖ "the length of the gap"

When people write ‖v‖ without a subscript, they mean L2.

By hand
v = [3, 4] ‖v‖₂ = √(3² + 4²) = √(9 + 16) = √25 = 5 ‖v‖₁ = |3| + |4| = 7

Try it: crow vs taxi

Drag the two points. The straight vermilion line is L2; the green staircase is L1.

Two things you can discover by dragging: L1 is never shorter than L2, and they are equal only when the points share a row or a column (the taxi doesn't need to turn).

Python
v = np.array([3.0, 4.0])
print("L1 length (city blocks)   :", np.linalg.norm(v, ord=1))
print("L2 length (straight line) :", np.linalg.norm(v))

A = np.array([0.2, 0.8, 0.6])
B = np.array([0.3, 0.7, 0.5])
C = np.array([0.9, 0.1, 0.2])
print("distance A to B:", round(np.linalg.norm(A - B), 3))
print("distance A to C:", round(np.linalg.norm(A - C), 3))
Output
L1 length (city blocks)   : 7.0
L2 length (straight line) : 5.0
distance A to B: 0.173
distance A to C: 1.068

A is much closer to B than to C. That single comparison is the whole idea behind k-nearest neighbours: to classify a new point, look at the labels of the closest stored points.

The scale trap

Story · who is Riya most like?

A bank wants to find customers similar to Riya (25 years old, earns ₹50,000 a month). Arjun is 65 and earns ₹51,000. Meera is 26 and earns ₹53,000. Any human would say Meera is more like Riya. Raw distance says the opposite, because a ₹3,000 gap is "3,000 units" while a 40-year gap is only "40 units". Income shouts; age whispers.

Python
#                 age  monthly income (₹)
riya  = np.array([25, 50_000])
arjun = np.array([65, 51_000])   # 40 years older, similar income
meera = np.array([26, 53_000])   # nearly the same age, ₹3,000 more

print("raw   riya→arjun:", round(np.linalg.norm(riya - arjun), 1))
print("raw   riya→meera:", round(np.linalg.norm(riya - meera), 1))

spread = np.array([12, 20_000])  # typical spread (std) of each feature across ALL customers
print("scaled riya→arjun:", round(np.linalg.norm((riya - arjun) / spread), 2))
print("scaled riya→meera:", round(np.linalg.norm((riya - meera) / spread), 2))
Output
raw   riya→arjun: 1000.8
raw   riya→meera: 3000.0
scaled riya→arjun: 3.33
scaled riya→meera: 0.17

After dividing each feature by its typical spread, a 40-year gap counts for a lot and a ₹3,000 gap counts for little, and Meera correctly comes out closest. This is what standardisation (for example scikit-learn's StandardScaler) does: it computes each column's spread from the training data and divides by it. Any method built on distances (k-NN, k-means, SVMs with RBF kernels) needs it.

Norms as a "complexity meter" for models

Norms also measure the size of a model's weight vector. Big weights usually mean a model that over-reacts to small changes in input. Regularisation adds the norm of the weights to the training objective so the model is pushed to keep them small: L1 for Lasso, squared L2 for Ridge.

Python
w = np.array([2.5, -1.8, 0.3, 4.1])      # a model's weights
print("L1 penalty (Lasso):", round(np.sum(np.abs(w)), 2))
print("L2 penalty (Ridge):", round(np.sum(w ** 2), 2))
Output
L1 penalty (Lasso): 8.7
L2 penalty (Ridge): 26.39
In ML

k-nearest neighbours, k-means clustering, anomaly detection ("how far is this point from everything normal?"), and Ridge / Lasso regularisation all rest on norms.

In business

Lookalike audiences: marketing finds the customers nearest to your best customers and targets them. Fraud alerts: a card transaction whose feature vector is far from that customer's usual transactions gets flagged for review. Both break badly if features aren't scaled first.

Check yourself

1. What is the L2 length of [6, 8]? And L1? Answer: 10 and 14.

2. Your features are "number of logins" (0–30) and "account balance" (₹0–₹50 lakh). You run k-means without scaling. What goes wrong? Answer: clusters will be formed almost entirely by balance; logins are ignored because their numbers are tiny by comparison.

4The dot product

If you learn one operation deeply, make it this one. A linear regression prediction is a dot product. Matrix multiplication is a grid of dot products. Attention in a transformer is dot products. Let's build it up from something you already do every week.

Step 1: it's a shopping bill

Intuition · the receipt

You buy 2 milk (₹40 each), 1 bread (₹60), 0 eggs (₹25) and 3 bananas (₹10). Your bill is 2×40 + 1×60 + 0×25 + 3×10 = ₹170. You took two lists, multiplied matching entries and added them up. That is the dot product.

Python
quantity = np.array([2, 1, 0, 3])        # milk, bread, eggs, bananas
price    = np.array([40, 60, 25, 10])    # ₹ per item

print("Line totals (*):", quantity * price)   # element-wise: still 4 numbers
print("Bill (@)       :", quantity @ price)   # dot product: one number
Output
Line totals (*): [80 60  0 30]
Bill (@)       : 170

Look closely at the two lines. * gave four line totals, still a vector. @ gave one number, the bill. This is golden rule 2 in action.

Step 2: it measures agreement

Intuition · will you enjoy this film?

Rate how much you care about action, dialogue, visuals and humour: [8, 3, 7, 2]. A critic rates how much a film delivers each: an action film is [9, 2, 8, 1], a rom-com is [1, 8, 3, 9]. Dot your preferences with each film. Where you care a lot and the film delivers a lot, the product is big. Where either is small, it adds little. The total is a "how well do we match" score.

Python
you    = np.array([8, 3, 7, 2])   # how much you care: action, dialogue, visuals, humour
action = np.array([9, 2, 8, 1])   # how much each film delivers
romcom = np.array([1, 8, 3, 9])

print("you · action film:", you @ action)
print("you · rom-com    :", you @ romcom)
Output
you · action film: 136
you · rom-com    : 71

Step 3: the geometry (why it measures agreement)

Math, decoded
a · b = a₁b₁ + a₂b₂ + … + aₙbₙ ← the algebra (what you compute) a · b = ‖a‖ × ‖b‖ × cos(θ) ← the geometry (what it means)

θ (theta) is the angle between the two arrows. cos(θ) is a number between −1 and 1 that depends only on that angle:

Anglecos θDot productMeaning
0° (same direction)1large positivestrong agreement
under 90°between 0 and 1positivebroadly agree
90° (perpendicular)0zerounrelated
over 90°negativenegativedisagree

Both formulas always give the same number. The first is how a computer calculates it; the second is how you should think about it.

Intuition · the shadow

Hold a pen (vector a) above a ruler (vector b) with a lamp directly overhead. The pen's shadow on the ruler shows "how much of a points along b". That shadow is called the projection. The dot product is the shadow's length multiplied by the ruler's length. Pen along the ruler: long shadow. Pen across the ruler: no shadow at all.

Try it: angle, shadow and dot product

Drag the arrow tips. The thick vermilion segment is the shadow (projection) of a on b. Try making them perpendicular.

Step 4: cosine similarity (agreement without the volume)

The dot product mixes two things: how aligned the arrows are, and how long they are. Sometimes length is noise. A superfan who rates everything 10 times higher than you has exactly your taste, but their dot products are 10 times bigger.

The fix is to divide out the lengths, which leaves only the angle:

cosine_similarity(a, b) = (a · b) / (‖a‖ × ‖b‖) = cos(θ)
Python
def cosine_similarity(a, b):
    return (a @ b) / (np.linalg.norm(a) * np.linalg.norm(b))

superfan = 10 * you          # identical taste, just rates everything 10x higher

print("dot :", you @ action, "vs", superfan @ action)
print("cos :", round(cosine_similarity(you, action), 3), "vs",
      round(cosine_similarity(superfan, action), 3))
print("cos with rom-com:", round(cosine_similarity(you, romcom), 3))
Output
dot : 136 vs 1360
cos : 0.989 vs 0.989
cos with rom-com: 0.508

The raw dot product says the superfan matches the action film ten times better than you. Cosine similarity says you both match it equally well (0.989), which is the truth. Cosine is the standard measure for comparing text embeddings, where long documents would otherwise always "win".

Step 5: a prediction is a dot product

Here is linear regression with the mystery removed. A model has learned one weight per feature: how much one unit of that feature is worth. To predict, it dots the weights with the features and adds a base amount (the bias).

Math, decoded
ŷ = w · x + b

"The predicted value (ŷ) is the weighted sum of the features (w · x) plus a starting value (b)." That's it. Logistic regression does the same thing and then squashes the result into a probability.

Python
# Predict a flat's price (₹ thousands) from [bedrooms, area in sq ft, parking spots]
w = np.array([120.0, 3.5, 40.0])   # learned weights: worth of one unit of each feature
b = 200.0                          # bias: the base price
x = np.array([4, 850, 2])          # one flat

y_hat = w @ x + b
print("Predicted price (₹ thousands):", y_hat)
Output
Predicted price (₹ thousands): 3735.0

Read it as a bill again: 4 bedrooms × 120 + 850 sq ft × 3.5 + 2 parking × 40 + 200 base = 3,735, so about ₹37.35 lakh. Training a model means finding good values for w and b; Article 2 shows how.

In ML
  • Linear and logistic regression: every prediction is one dot product.
  • Neurons: each neuron in a neural network computes a dot product of its inputs and weights, then applies a bend (an activation function).
  • Embeddings and search: semantic search ranks documents by cosine similarity between the query's vector and each document's vector.
  • Attention: transformers decide which words to focus on using dot products (a toy version is in Section 10).
In business

A classic credit scorecard is literally a weighted sum of applicant features: a dot product. Résumé-to-job matching tools embed both texts and use cosine similarity. "Customers who liked this also liked…" panels compare item vectors the same way.

Check yourself

1. Compute [1, 2] · [2, −1]. What does the answer say about the arrows? Answer: 2 − 2 = 0. They are perpendicular.

2. Two news articles have cosine similarity 0.95 but one is ten times longer. Are they about the same topic? Answer: Very likely yes. Cosine ignores length and looks only at direction.

3. For 1-D arrays a and b, what's the difference between a * b and a @ b? Answer: * returns a vector of products; @ returns their sum, a single number.

5Matrix basics

Intuition · a spreadsheet that can act

A matrix is a spreadsheet: numbers in rows and columns. The new idea is that a matrix is also a stack of row vectors (customers) and, read sideways, a set of column vectors (features). Everything from the last four sections applies to its rows and columns.

Adding and scaling matrices

These work exactly like vectors: entry by entry, and both matrices must have the same shape.

Python
# Revenue (₹ thousands): rows = stores, columns = products
q1 = np.array([[120, 80],
               [ 95, 60]])
q2 = np.array([[130, 70],
               [100, 65]])

print("Half-year total:\n", q1 + q2)
print("Q1 with 18% GST:\n", 1.18 * q1)
Output
Half-year total:
 [[250 150]
 [195 125]]
Q1 with 18% GST:
 [[141.6  94.4]
 [112.1  70.8]]

Transpose: turning the table on its side

Intuition · rotate the printout

Print a table, then read it so that what used to be rows are now columns. Row 1 becomes column 1, row 2 becomes column 2. A shape of (2, 3) becomes (3, 2). Nothing is calculated; numbers just move.

By hand
M = [[1, 2, 3], Mᵀ = [[1, 4], [4, 5, 6]] [2, 5], [3, 6]] entry (i, j) of Mᵀ = entry (j, i) of M
Python
M = np.array([[1, 2, 3],
              [4, 5, 6]])
print(M.shape, "→", M.T.shape)
print(M.T)
Output
(2, 3) → (3, 2)
[[1 4]
 [2 5]
 [3 6]]

Why bother? Because the shape rule for multiplication (Section 8) is strict, and the transpose is how you line shapes up. You will see Xᵀ in the regression formula, and movies.T in the recommender later.

Element-wise product and the identity matrix

The element-wise product (also called the Hadamard product, written ⊙) multiplies matching entries. A common use is a mask: multiply by 1 to keep, by 0 to hide. Neural networks use exactly this for dropout, randomly switching off some neurons during training so the network can't lean on any single one.

The identity matrix I has 1s on the diagonal and 0s elsewhere. Multiplying by it changes nothing, the way multiplying a number by 1 changes nothing. It matters as the reference point for "undo" in Section 9: A @ A⁻¹ = I.

Python
activations = np.array([1.5, -0.3, 2.1, 0.8, 1.2])
keep_mask   = np.array([1,    1,   0,   1,   0 ])   # 0 = switched off this round
print("Masked :", activations * keep_mask)

I = np.eye(3)
A = np.array([[2., 1, 0], [0, 3, 1], [1, 0, 4]])
print("I @ A equals A?", np.allclose(I @ A, A))
Output
Masked : [ 1.5 -0.3  0.   0.8  0. ]
I @ A equals A? True
Common mistake · * vs @ on matrices

For two (2, 2) matrices, both A * B and A @ B run without error and both return a (2, 2) result, with completely different numbers. NumPy can't warn you. Ask yourself: "do I want matching entries multiplied (*), or rows combined with columns (@)?"

In business

A monthly report of revenue by store × product is a matrix. Adding two months, applying tax across the board, or masking out discontinued products are the operations above, applied to thousands of cells at once.

Check yourself

1. X has shape (1000, 12). What is the shape of Xᵀ? Answer: (12, 1000).

2. Can you add a (3, 2) matrix to a (2, 3) matrix? Answer: No, shapes must match. (You could add the first to the transpose of the second.)

6Matrix × vector: the operation ML runs most

Many tutorials jump straight to multiplying two matrices. That skips the most important case: a matrix times a vector. Understand this one in two ways and matrix-matrix multiplication becomes easy.

Reading 1: the row view (many dot products)

Take each row of the matrix and dot it with the vector. You get one number per row.

By hand · row view
A x A @ x [[1, 2], [10, [1×10 + 2×1, [12, [3, 4], × 1] = 3×10 + 4×1, = 34, [5, 6]] 5×10 + 6×1] 56] (3×2) (2,) (3,)

3 rows in, 3 numbers out. The vector's length (2) had to match the number of columns (2).

Reading 2: the column view (a recipe)

Intuition · a recipe

Think of each column of A as an ingredient's profile, say, the protein, carbs and fat in one scoop. The vector x says how many scoops of each ingredient you use. The result is the profile of the whole meal: 10 scoops of ingredient 1 plus 1 scoop of ingredient 2.

By hand · column view
A @ x = 10 × [1, 3, 5] + 1 × [2, 4, 6] = [10, 30, 50] + [2, 4, 6] = [12, 34, 56] ← same answer

Matrix × vector is a weighted mix of the matrix's columns, with the vector supplying the weights.

7Matrices as transformations of space

Now the column view pays off. A 2×2 matrix multiplies any 2D point and returns another 2D point. Apply it to every point on the plane and the whole plane moves: it stretches, rotates, slants or flips. A matrix is a machine that reshapes space.

Intuition · two arrows decide everything

Start with two reference arrows: î = [1, 0] (one step right) and ĵ = [0, 1] (one step up). Any point is "some amount of î plus some amount of ĵ". The matrix's first column says where î lands and its second column says where ĵ lands. Every other point follows along, because it was built from î and ĵ.

"Linear" means the grid stays a grid: lines stay straight, parallel lines stay parallel and equally spaced, and the origin doesn't move.

Try it: the matrix transformer

Pick a preset or type your own numbers. The faint grid is the original plane; the coloured grid is after the matrix. Watch the unit square and the letter F.

M =

Things to try in the widget:

  • Stretch: the square becomes a 2 × 1 rectangle. Its area doubles.
  • Rotate: everything turns, and the area stays the same.
  • Flip: the F is mirrored. The area is the same size, but the readout reports it as negative.
  • Collapse: the whole plane is squashed onto one line. The square has no area left.

The number in the readout is the determinant: the factor by which the matrix scales area. If it is 2, every shape doubles in area. If it is negative, space was flipped. If it is 0, space collapsed to a line or a point, and information was destroyed. We use this in Section 9.

By hand · determinant of a 2×2
M = [[a, b], [c, d]] det(M) = a×d − b×c Shear [[1, 0.8], [0, 1]]: 1×1 − 0.8×0 = 1 (slants, no change in area) Stretch [[2, 0], [0, 1]]: 2×1 − 0×0 = 2 (area doubles)
Python
shear = np.array([[1.0, 0.8],
                  [0.0, 1.0]])
square = np.array([[0, 0], [1, 0], [1, 1], [0, 1]], dtype=float)  # rows = corner points

print(square @ shear.T)           # transforms every point at once
print("Area scaling (det):", round(np.linalg.det(shear), 3))
Output
[[0.  0. ]
 [1.  0. ]
 [1.8 1. ]
 [0.8 1. ]]
Area scaling (det): 1.0

A note on the code: our points sit in rows (golden rule 1). The textbook form M @ p works on a single column-shaped point, so to transform a whole stack of row-points at once we write points @ M.T. It gives exactly the same answers as doing M @ p for each point.

In ML
  • Feature scaling is a stretch along each axis.
  • PCA finds a rotation of your data's axes so the first new axis captures the most variation. Your dashboards' "2D projection of customers" is often this.
  • A neural network layer is a matrix transformation followed by a bend (the activation). Stacking layers repeatedly reshapes space until the classes you care about can be separated by a simple cut.
Check yourself

1. Where does î land under [[3, 1], [2, 5]]? Answer: [3, 2], the first column.

2. A matrix has determinant −3. Describe what it does to area. Answer: triples it and flips orientation (mirror image).

8Matrix × matrix

With matrix × vector understood, matrix × matrix is just several matrix-vector products side by side. Treat each column of B as a separate vector, multiply it by A, and stack the results as the columns of the answer.

Equivalently, every entry of the result is one dot product: entry (i, j) = row i of A · column j of B.

Intuition · workers and tasks

Each row of A is a worker's skill profile (welding, painting, wiring). Each column of B is a task's requirements in the same three skills. Entry (i, j) of A @ B is the dot product of worker i and task j: how well this worker fits this task. The whole product is the fit score of every worker against every task, in one operation.

Try it: step through A @ B

Each step fills one cell: the highlighted row of A dotted with the highlighted column of B.

The shape rule: dominoes

Math, decoded
(m × k) @ (k × n) → (m × n) └──────┘ inner numbers must match; the outer numbers are the answer's shape

Like dominoes, the touching ends must match. Why? Each output entry is a dot product of a row of A (length k) with a column of B (length k). Dot products need equal lengths. That's the whole reason.

Order matters: A @ B is not B @ A

Intuition · socks and shoes

When applied to a vector, (A @ B) @ x means "apply B first, then A". Socks then shoes is not the same as shoes then socks. Rotating then stretching gives a different picture from stretching then rotating. The code above shows A @ B and B @ A giving different numbers, and P @ Q and Q @ P not even having the same shape.

A real use: a recommender in one line

Give each user a taste vector and each movie a profile vector over the same genres. The score of a user for a movie is their dot product. Every user against every movie? One matrix multiplication. Note the transpose: movies is stored rows-as-movies (golden rule 1), so we flip it to put genres in its rows and line the shapes up.

                   [0.6, 0.2, 0.9],   # Orbit Run

In ML

In business

9Determinant, inverse and solving equations

The determinant, revisited

You met the determinant in the transformer widget as the "area scaling factor". Here are the cases side by side:

                ("mix",      [[2, 1], [1, 3]]),
                ("rotate",   [[0, -1], [1, 0]]),
                ("flip",     [[0, 1], [1, 0]]),
                ("collapse", [[1, 2], [2, 4]])]:
    print(f"{name:9s} det = {np.linalg.det(np.array(M)):+.1f}")
Output
stretch   det = +2.0
mix       det = +5.0
rotate    det = +1.0
flip      det = -1.0

The one that matters most in ML is the last: det = 0 means the matrix collapses space. Two different input points can land on the same output point, so you can no longer tell them apart. Information is lost.

The inverse: the undo button

Intuition · Ctrl+Z

If A stretches space by 2 along x, its inverse A⁻¹ shrinks by 2 along x. Do one then the other and you are back where you started: A⁻¹ @ A = I. But if A squashed the plane onto a line, there is no undo. You can't un-squash, because you don't know where on the original plane each point came from. That is why an inverse exists only when det ≠ 0.

Solving equations: what did the pens cost?

Story · two bills, two unknowns

Your office has two stationery bills. Bill 1: 3 pens and 2 notebooks for ₹190. Bill 2: 1 pen and 4 notebooks for ₹230. What does one pen cost? That is two equations with two unknowns, and a matrix writes it compactly as A @ p = totals.

By hand
3p + 2n = 190 1p + 4n = 230 Double the first: 6p + 4n = 380 Subtract second : 5p = 150 → p = 30 Back-substitute : 30 + 4n = 230 → n = 50
Python
# Bill 1: 3 pens + 2 notebooks = ₹190
# Bill 2: 1 pen  + 4 notebooks = ₹230
A = np.array([[3.0, 2.0],
              [1.0, 4.0]])
totals = np.array([190.0, 230.0])

print("Unit prices:", np.linalg.solve(A, totals))
print("A⁻¹:\n", np.linalg.inv(A))
Output
Unit prices: [30. 50.]
A⁻¹:
 [[ 0.4 -0.2]
 [-0.1  0.3]]
Practical advice · solve, don't invert

Mathematically, p = A⁻¹ @ totals. In code, prefer np.linalg.solve(A, totals). It is faster and more numerically accurate, because it never builds the inverse explicitly. Compute inv only when you need the inverse matrix itself.

Python
same_info = np.array([[1.0, 2.0],
                      [2.0, 4.0]])     # row 2 is just 2 x row 1
try:
    np.linalg.inv(same_info)
except np.linalg.LinAlgError as e:
    print("Cannot invert:", e)
Output
Cannot invert: Singular matrix

Why this matters: multicollinearity

Intuition · two rulers measuring the same thing

Suppose a dataset has "height in cm" and "height in inches". Those columns carry identical information. Ask a linear model how much each one matters and it can't decide: 1 part cm + 0 parts inches works, and so does 0 parts cm + 2.54 parts inches, and infinitely many mixes in between. In matrix terms, the matrix XᵀX that regression needs to undo is (nearly) collapsed.

Real data is rarely exactly collapsed, so the determinant is rarely exactly 0. A better gauge is the condition number: roughly, how much a tiny wobble in the data can swing the answer. Values in the hundreds are fine. Values like 10¹⁶ mean "practically collapsed; the answer is noise".

Python
rng = np.random.default_rng(0)
height_cm = rng.normal(170, 10, 100)
height_in = height_cm / 2.54            # the same information in another unit
weight_kg = rng.normal(70, 12, 100)

redundant = np.column_stack([height_cm, height_in])
healthy   = np.column_stack([height_cm, weight_kg])
print(f"condition number, redundant: {np.linalg.cond(redundant.T @ redundant):.1e}")
print(f"condition number, healthy  : {np.linalg.cond(healthy.T @ healthy):.1e}")
Output
condition number, redundant: 2.4e+16
condition number, healthy  : 2.8e+02

Preview: the regression formula, decoded

Ordinary least squares has a famous one-line solution, the normal equation:

Math, decoded
w = (XᵀX)⁻¹ Xᵀ y

Read it right to left. Xᵀy: how strongly each feature lines up with the target (a dot product per feature). XᵀX: how the features overlap with each other. Multiplying by (XᵀX)⁻¹ undoes that overlap so each feature gets credit only for what it uniquely explains. This is why collinear features break it: the overlap can't be undone.

Python
rng = np.random.default_rng(42)
n = 200
X_raw = rng.normal(size=(n, 2))
X = np.column_stack([np.ones(n), X_raw])      # a column of 1s carries the bias
true_w = np.array([5.0, 2.0, -3.0])
y = X @ true_w + rng.normal(0, 0.5, n)        # data generated with a little noise

w_hat = np.linalg.solve(X.T @ X, X.T @ y)     # the "normal equation"
print("true weights :", true_w)
print("found weights:", w_hat.round(3))
Output
true weights : [ 5.  2. -3.]
found weights: [ 4.965  1.991 -3.027]

The recovered weights are within a few hundredths of the true ones; the rest is noise. For very large datasets, building and solving XᵀX gets expensive, so models are usually trained with gradient descent instead. That is the subject of Article 2.

In business

Driver analysis: when a team presents "price is the biggest driver of churn" from a regression, check for collinearity first. If price and plan tier move together, the coefficients can swap or flip sign between runs. A quick condition-number or VIF check before the meeting saves an embarrassing correction later. Mix problems: recovering unit costs from combined invoices, or blend proportions from lab readings, is solving a linear system.

Check yourself

1. det([[2, 4], [1, 2]])? Can it be inverted? Answer: 2×2 − 4×1 = 0. No, its rows carry the same information.

2. Your regression's coefficients change wildly when you drop 1% of rows. What should you suspect? Answer: multicollinearity. Check the condition number or VIFs.

Python
X = np.array([[ 0.5,  1.0, -0.2],
              [ 0.1, -0.4,  0.9],
              [ 1.2,  0.3,  0.0],
              [-0.6,  0.8,  0.4]])     # (4 samples, 3 features)
W = np.array([[ 0.2, -0.5],
              [ 0.7,  0.1],
              [-0.3,  0.6]])          # (3 inputs, 2 neurons)
b = np.array([0.1, -0.2])             # one bias per neuron

Z = X @ W + b                         # (4, 3) @ (3, 2) → (4, 2)
H = np.maximum(0, Z)                  # ReLU: negative values become 0
print("Z:\n", Z.round(2))
print("H:\n", H.round(2))

Each column of W is one neuron's weight vector, and each entry of Z is one sample dotted with one neuron. ReLU then zeroes the negatives; that bend is what lets stacked layers learn curved patterns rather than just straight-line ones. Deep learning is this block repeated, with the weights learned by the calculus of Article 2.

A toy look at attention

Intuition · a word asks its neighbours

"Bank" means one thing in "river bank" and another in "bank loan". A transformer resolves this by letting each word look at the words around it and borrow meaning from the ones it matches best. "Matches best" is measured with dot products.

Below, each word gets a hand-made 3-number vector scoring how much it relates to water, money and place. "Bank" starts ambiguous: [0.6, 0.6, 0.5]. We dot it with every word in its sentence, turn the scores into shares that add to 1 (softmax), and take the weighted mix of the sentence's vectors.

Python
#                    water money place
emb = {"river": np.array([1.0, 0.0, 0.3]),
       "bank":  np.array([0.6, 0.6, 0.5]),
       "loan":  np.array([0.0, 1.0, 0.1]),
       "boat":  np.array([0.9, 0.1, 0.2])}

def softmax(s):
    e = np.exp(s - s.max())
    return e / e.sum()

def bank_in_context(sentence):
    S = np.stack([emb[w] for w in sentence])   # (words, 3)
    weights = softmax(S @ emb["bank"])         # how much "bank" listens to each word
    return weights.round(2), (weights @ S).round(2)

print("river bank boat →", bank_in_context(["river", "bank", "boat"]))
print("loan bank       →", bank_in_context(["loan", "bank"]))
Output
river bank boat → (array([0.31, 0.39, 0.3 ]), array([0.81, 0.26, 0.35]))
loan bank       → (array([0.42, 0.58]), array([0.35, 0.77, 0.33]))

Same starting vector, different sentences, different results. Next to "river" and "boat", bank's new vector leans to water (0.81). Next to "loan" it leans to money (0.77). The context changed the meaning through nothing but dot products, a softmax and a weighted sum.

Honesty note

This is a deliberate simplification. Real transformers learn their embeddings (hundreds of dimensions, not 3), and they first multiply them by three learned matrices to get separate query, key and value vectors, then scale the scores by √d before the softmax. The core move, "dot product to score, softmax to weigh, weighted sum to mix", is exactly what you just ran.
